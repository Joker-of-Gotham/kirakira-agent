# Shell completion

Shell completion is generated by the **`kirakira-agent completion`** command (`packages/cli/src/commands/completion.ts`). It does not install itself; you redirect output into a file your shell loads.

## Supported shells

The command accepts one required positional argument:

- `bash`
- `zsh`
- `fish`
- `powershell`

Implementation: `switch (args.shell)` dispatching to `generateBashCompletion()`, `generateZshCompletion()`, `generateFishCompletion()`, `generatePowershellCompletion()` in the same file.

## What gets completed

Generators embed the **top-level command list** matching the product taxonomy:

`init`, `exec`, `login`, `logout`, `config`, `session`, `skill`, `mcp`, `plugin`, `registry`, `trace`, `eval`, `doctor`, `completion`, `self-update`

Subcommand completion is **not** exhaustively encoded in the static scripts; after installation, prefer regenerating scripts when new commands ship, or extend the generator functions to call `kirakira-agent --help` / JSON help if you build richer installers.

## Install examples

### Bash

```bash
kirakira-agent completion bash > /etc/bash_completion.d/kirakira-agent  # or user-local path
```

The template defines `_kirakira_agent` using `compgen -W "$commands"`.

### Zsh

```bash
kirakira-agent completion zsh > ~/.zsh/completions/_kirakira-agent
```

Uses `#compdef kirakira-agent` and `_describe`.

### Fish

```bash
kirakira-agent completion fish | source
# or save under ~/.config/fish/completions/kirakira-agent.fish
```

### PowerShell

```bash
kirakira-agent completion powershell >> $PROFILE
```

Uses `Register-ArgumentCompleter` with a string array filter.

## oclif note

The project uses `@oclif/core` (`packages/cli/package.json`). For dynamic completion wired to oclif’s built-in helpers, you can evolve `completion.ts` to delegate to oclif plugins; the current implementation is intentionally self-contained and offline-friendly.
